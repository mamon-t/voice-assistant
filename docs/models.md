# Модели: состав, лицензии, замеры

## Что используется

| Назначение | Модель | Размер | Лицензия |
|---|---|---|---|
| VAD | `silero_vad.onnx` | 0.6 МБ | MIT |
| ASR, основной профиль | `sherpa-onnx-small-zipformer-ru-2024-09-18` (int8) | 110 МБ | Apache-2.0 |
| ASR, запасной (шум) | `sherpa-onnx-nemo-transducer-giga-am-v3-russian-2025-12-16` | 167 МБ | MIT |
| ASR, запасной (CTC) | `sherpa-onnx-nemo-ctc-giga-am-v3-russian-2025-12-16` | 163 МБ | MIT |
| ASR, мультиязычный | `sherpa-onnx-whisper-base` (int8) | 208 МБ | MIT |

Все модели скачиваются из релизов
[k2-fsa/sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/releases/tag/asr-models)
и в репозиторий не входят.

```bash
mkdir -p ~/.voice_models && cd ~/.voice_models
R=https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models

wget $R/silero_vad.onnx
wget $R/sherpa-onnx-small-zipformer-ru-2024-09-18.tar.bz2
wget $R/sherpa-onnx-nemo-transducer-giga-am-v3-russian-2025-12-16.tar.bz2   # опционально
wget $R/sherpa-onnx-nemo-ctc-giga-am-v3-russian-2025-12-16.tar.bz2           # опционально
wget $R/sherpa-onnx-whisper-base.tar.bz2                                     # опционально
for f in *.tar.bz2; do tar xf "$f" && rm "$f"; done
```

## Методика замеров

* Тестовая фраза (русский, синтез речи): «Привет. Это последняя итерация
  голосового помощника. Набор текста работает в любом поле ввода.» — 7.16 с
  полезного аудио в файле 7.68 с, 24 кГц моно → 16 кГц.
* Прогон **через код проекта** (`tools/vad-asr-test --config`), то есть
  VAD → сегмент → ASR → постобработка, а не отдельным декодером.
* 2 потока, серверный x86-64. **На Celeron время умножать на 3–5.**
* `RTF = время декодирования / длительность аудио`; меньше 1 — успевает за реальным
  временем.

## Контрольные тексты

Одна и та же русская запись:

```
эталон             : Привет. Это последняя итерация голосового помощника.
                     Набор текста работает в любом поле ввода.
zipformer-ru       : привет это последняя итерация голосового помощника
                     набор текста работает в любом поле ввода            ✓
GigaAM v3 RNN-T    : привет это последняя итерация голосового помощника
                     набор текста работает в любом поле ввода            ✓
Whisper base       : Привет! Это последняя итерация голосового помощника.
                     На борте к стаработают в любом поле в вода.         ✗
Whisper tiny       : Привет! Это последнее и тирация голосового помощника.
                     На бортех стар работает в любом поле вода.          ✗
SenseVoice         : RIVIE PALII IT RDS A GLSS OF OONICAL BONE POEODA    ✗
```

Родные тестовые WAV моделей (проверка, что тракт не врёт):

```
zipformer-ru : «родион потапыч высчитывал каждый новый вершок углубления
                и давно определил про себя»                              ✓
GigaAM v3    : «у лукоморья дуб зеленый»                                  ✓
SenseVoice   : «开放时间早上九点至下午五点» (китайский)                     ✓
```

## Почему SenseVoice удалена

SenseVoice-small обучена на zh / en / ja / ko / yue — русского среди языков нет.
Проверено **официальным** бинарником `sherpa-onnx-offline`, то есть дело не
в нашей обёртке: на русской речи она выдаёт латинскую кашу и определяет язык как
`<|yue|>`, при этом на китайском работает идеально. Держать модель 237 МБ,
которая не решает основную задачу, смысла нет.

## Почему zipformer-ru — основной профиль

* в 3–5 раз быстрее GigaAM при одинаковом тексте на чистом материале;
* 110 МБ вместо 163–297 МБ — меньше ОЗУ и диска;
* поддерживает hotwords (transducer + `modified_beam_search`), что подтверждено
  замером — см. [hotwords-and-punctuation.md](hotwords-and-punctuation.md).

Слабое место: на записи с диктантными словами он без бустинга терял «а не»
(распознал как «они»), тогда как GigaAM v3 вытянул фразу целиком. Отсюда схема:
zipformer по умолчанию, GigaAM — переключаемый профиль для шума.

## Роль GigaAM

GigaAM v3 по данным авторов даёт −30 % WER на новых доменах: callcenter, музыка,
голосовые сообщения, атипичная речь. То есть на реальном микрофоне с шумами он
вытянет там, где zipformer ошибётся. Цена — в 3–5 раз больше времени декодирования:
на Celeron RTF будет около 0.6–1.0, фраза в 5 с декодируется 3–5 с. Для диктовки
по сегментам терпимо, для комфортной непрерывной работы — впритык.

Большая `sherpa-onnx-zipformer-ru-2024-09-18` (297 МБ) не дала выигрыша ни
в точности, ни в скорости на тестовом материале — брать её незачем.

## Роль Whisper

Оставляем запасным профилем, по умолчанию не активен:

* единственный из проверенных ставит пунктуацию и заглавные сам и нормализует
  числа («October 3, 2026», «about 25 source files»);
* единственный мультиязычный — английский у него отличный
  («Hello, Mikael. This is the final iteration of the Voice Assistant.»);
* в профильной схеме ничего не стоит, пока не выбран: модель не грузится.

Русский у него заметно хуже, и он самый медленный, поэтому основным быть не может.

## Про пунктуацию в GigaAM

Знаки препинания и нормализацию текста в GigaAM умеют только варианты
`v3_e2e_ctc` / `v3_e2e_rnnt`. В ONNX их нет: на HuggingFace во всех ревизиях
(`ctc`, `rnnt`, `e2e_ctc`, `e2e_rnnt`) лежит только `pytorch_model.bin`
(~442–449 МБ), а в релизах sherpa-onnx есть ровно четыре GigaAM-модели,
ни одной e2e. Самостоятельный экспорт теоретически возможен
(`model.to_onnx()` универсален, в `gigaam/onnx_utils.py` e2e-специфики нет),
но конвертера под sherpa-onnx не существует, а токены у e2e — sentencepiece,
а не 34 буквы. Поэтому пунктуация решена иначе —
см. [hotwords-and-punctuation.md](hotwords-and-punctuation.md).

## Рекомендации для слабого железа

| Железо | Профиль | `num_threads` | Ожидание |
|---|---|---|---|
| Celeron, 4 ГБ | zipformer-ru | 1 | RTF ≈ 0.15–0.25, фраза в 5 с декодируется ~1 с |
| Celeron, 8–16 ГБ | zipformer-ru | 2 | RTF ≈ 0.1–0.2 |
| то же, шумная обстановка | gigaam-v3 | 2 | RTF ≈ 0.6–1.0 |
| современный 4-ядерник | любой | 2–4 | RTF < 0.1 |

`int8`-варианты моделей обязательны: fp32 в 2–3 раза больше и медленнее
при том же качестве на этой задаче.
