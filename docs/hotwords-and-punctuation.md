# Подсказки (hotwords) и пунктуация

Два связанных механизма: оба про то, как заставить модель выдавать нужные слова
и как из строчки слов получить читаемый текст.

---

## Часть 1. Подсказки пользователя

### Что реально поддерживается

Проверено по исходникам sherpa-onnx: `hotwords_file` и `hotwords_score` читаются
только в

* `offline-recognizer-transducer-impl.h` (zipformer-ru),
* `offline-recognizer-transducer-nemo-impl.h` (GigaAM RNN-T),
* а также FunASR-Nano и Qwen3-ASR (не используются).

И только при `decoding_method=modified_beam_search` — именно там строится
контекстный граф. У Whisper, SenseVoice и CTC-моделей подсказки игнорируются
полностью, и наши реализации честно пишут об этом предупреждение в лог
(`setHotwords()` не делает вид, что работает).

Отсюда правило: **нужны подсказки — берите профиль с `engine=transducer`**.

### Замер: подсказки меняют результат

Запись 11.84 с, zipformer-ru, `modified_beam_search`:

```
без подсказок  : итерация голосового помощника набор текста работает в любом поле ввода
с подсказками  : привет это последняя итерация голосового помощника набор текста
                 работает в любом поле ввода
                 ^^^^^^^^^^^^^^^^^^^ восстановлено потерянное начало фразы
RTF: 0.063 против 0.029 (greedy) — луч дороже, но результат полнее
```

Побочный вывод: `modified_beam_search` точнее `greedy_search` сам по себе,
поэтому в `TransducerRecognizer::Options` он стоит по умолчанию.

### Откуда берутся подсказки

```
~/.config/voice-assistant/user_hotwords.txt      свои слова: имена, термины
~/.config/voice-assistant/commands_hotwords.txt  диктантные команды
CommandDictionary::phrases()                     словарь команд из кода
TextPostProcessor::punctuationPhrases()          «точка», «запятая», … (добавляет VoicePipeline)
        ↓
   VoicePipeline::applyHotwords()  →  IRecognizer::setHotwords(words, score)
```

Формат файлов — по одной фразе в строке, `#` — комментарий. Перечитывание:
`ApplicationController::reloadHotwords()` (или метод `reloadHotwords` по D-Bus),
после чего `HotwordsManager` шлёт `hotwordsChanged`, и подсказки применяются
к уже созданному распознавателю без перезапуска.

Сила бустинга — `[asr] hotwords_score` (по умолчанию 2.0) или ключ
`hotwords_score` внутри профиля.

### BPE-словарь: почему он нужен

У zipformer-ru токены — куски BPE (`▁на`, `бо`, `р`), а не слова. Чтобы подсказки
можно было писать по-человечески, sherpa-onnx кодирует их через `ssentencepiece`,
которому нужен **текстовый** словарь вида `токен score`. Бинарный `bpe.model`
не годится: на нём библиотека падает с сообщением

```
Each line in vocab should contain two items (seperate by space), the first one is bpe token …
```

Словарь делается один раз:

```bash
python3 -m pip install --user sentencepiece
python3 tools/gen_bpe_vocab.py \
    ~/.voice_models/sherpa-onnx-small-zipformer-ru-2024-09-18/bpe.model \
    ~/.voice_models/sherpa-onnx-small-zipformer-ru-2024-09-18/bpe.vocab
# кусков в модели: 500 | записано: 500 | пропущено: 0
```

и прописывается в профиле:

```ini
bpe_vocab=sherpa-onnx-small-zipformer-ru-2024-09-18/bpe.vocab
modeling_unit=bpe
```

У GigaAM токены посимвольные (34 штуки), поэтому `bpe_vocab` не нужен вовсе.

Если словарь не генерировать, подсказки тоже работают — но их придётся писать
уже разобранными на токены из `tokens.txt` (`▁на бо р`). Словарь удобнее.

### Ключевой эффект: диктантные слова надо бустить

ASR **проглатывает** служебные слова: модель обучена на живой речи и не ожидает
диктантных команд. Замер на одной записи:

| «точка»/«запятая» в hotwords | что выдал ASR |
|---|---|
| нет | `…помощника набор текста работает запятая …речи вопросительный` — оба «точка» потеряны |
| **да** | `…помощника **точка** набор текста работает **запятая** …речи **вопросительный знак**` |

Поэтому `VoicePipeline::applyHotwords()` примешивает диктантные знаки к списку
пользователя **автоматически**, когда включены `voice_punctuation` и профиль —
transducer в `modified_beam_search`. Слово «пробел» в авто-буст не входит:
бустить его рискованнее, чем полезно (модель начнёт вставлять его там, где
его не произносили).

## Часть 2. Пунктуация

### Почему не моделью

* Русской модели пунктуации в sherpa-onnx нет — есть только
  `sherpa-onnx-punct-ct-transformer-zh-en-vocab272727` (279 МБ, китайский
  и английский).
* GigaAM с пунктуацией — это `v3_e2e_*`, которых в ONNX не существует
  (см. [models.md](models.md)).
* Zipformer-ru и обычный GigaAM v3 выдают текст строчными буквами и без знаков.

API на будущее есть: `cxx::OfflinePunctuation` в `sherpa-onnx/c-api/cxx-api.h`.
Когда появится русская модель, она подключится отдельным классом без правки
контроллера и пайплайна.

### Что делаем вместо этого

Три приёма в `TextPostProcessor`:

1. **Голосовые знаки** — слова превращаются в символы.
2. **Граница сегмента VAD = граница предложения** — заглавная в начале, точка
   в конце, заглавная после `. ! ?` и после перевода строки.
3. **Косметика** — пробел перед знаком убирается, повторы пробелов схлопываются,
   пробел после `(` и перед `)` не ставится.

Пример полного прохода:

```
ASR   : привет это последняя итерация голосового помощника точка набор текста
        работает запятая а не просто распознавание речи вопросительный знак
итог  : Привет это последняя итерация голосового помощника. Набор текста
        работает, а не просто распознавание речи?
```

### Таблица голосовых знаков

| Произносим | Получаем |
|---|---|
| точка | `.` |
| запятая | `,` |
| вопросительный знак / знак вопроса / вопросительный | `?` |
| восклицательный знак / восклицательный | `!` |
| двоеточие | `:` |
| точка с запятой | `;` |
| тире | `—` |
| дефис | `-` |
| абзац / новая строка / перенос строки / красная строка | перевод строки |
| открывающая скобка / закрывающая скобка | `(` / `)` |
| пробел | пробел (в авто-буст hotwords не попадает) |

Совпадение ищется **самой длинной фразой вперёд**: «точка с запятой» не
превращается в «точка» + хвост. Одиночные «вопросительный» и «восклицательный»
добавлены страховкой — ASR иногда теряет слово «знак».

Список меняется в коде (`TextPostProcessor::defaultRules()` +
`setRules()`); вынести его в конфиг — очевидное следующее улучшение.

### Настройки

```ini
[text]
auto_punctuate=true       ; заглавные + точка в конце (границы сегмента VAD)
voice_punctuation=true    ; слова-знаки
```

`voice_punctuation=false` отключает и замену слов, и автоматический буст
диктантных знаков в hotwords.

### Проверка

```bash
# unit-тесты постпроцессора (12 проверок)
cd build && ./tests/test_voice_units voicePunctuationInline multiwordPunctuationPhrase

# живой прогон: сказать «… точка … запятая …» и посмотреть пары raw/text
./tools/vad-asr-test запись.wav --config ~/.config/voice-assistant/settings.ini
```

Инструмент печатает обе строки — `raw` (что выдал ASR) и `text` (что ушло
в приложение), так что сразу видно, где ошибка модели, а где постобработки.
