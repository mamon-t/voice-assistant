# Конфигурация

Файл: `~/.config/voice-assistant/settings.ini` (формат INI, читается `QSettings`).
Шаблон с комментариями лежит в `config/settings.ini` репозитория.

Рядом кладутся два файла подсказок:

```
~/.config/voice-assistant/commands_hotwords.txt   диктантные команды (уже заполнен)
~/.config/voice-assistant/user_hotwords.txt       свои слова: имена, термины, названия
~/.config/voice-assistant/commands.txt            свои команды (необязательно)
```

## Пути к моделям

`ConfigManager::resolvePath()` понимает три формы, поэтому конфиг переносим
между машинами:

| Запись | Во что раскрывается |
|---|---|
| `sherpa-onnx-small-zipformer-ru-2024-09-18/encoder.int8.onnx` | `~/.voice_models/…` |
| `~/models/zipformer-ru/encoder.int8.onnx` | от домашнего каталога |
| `/opt/voice-models/encoder.int8.onnx` | как есть |

Корневой каталог моделей — `~/.voice_models` (`ConfigManager::modelsPath()`).

## `[asr]` — профили распознавания

```ini
[asr]
active=zipformer-ru
profiles=zipformer-ru,gigaam-v3,gigaam-v3-ctc,whisper-base
num_threads=2          ; значение по умолчанию для профилей, где num_threads не задан
hotwords_score=2.0     ; сила бустинга подсказок
```

`active` — какой профиль грузить при старте. `profiles` — список для переключения
(трей, D-Bus, `ApplicationController::switchAsrProfile()`).

⚠️ `profiles` перечисляются через запятую, и `QSettings` возвращает такое значение
как `QStringList`, а не строку. `ConfigManager::asrProfileNames()` это учитывает;
если читать значение через `.toString()` напрямую, получится пустая строка.

## `[asr_<имя>]` — описание профиля

Общие ключи:

| Ключ | Значения | Комментарий |
|---|---|---|
| `engine` | `transducer`, `nemo-ctc`, `whisper` | определяет, какие пути обязательны |
| `tokens` | путь | словарь токенов модели |
| `num_threads` | 1–4 | для Celeron ставьте 1–2 |
| `decoding_method` | `modified_beam_search`, `greedy_search` | hotwords работают только в `modified_beam_search` |
| `max_active_paths` | 4 | ширина луча |
| `hotwords_score` | 2.0 | переопределяет общее значение |
| `commands_hotwords_score` | 2.0 | скор для фраз команд из словаря |
| `punctuation_hotwords_score` | 2.0 | скор для диктантных знаков; замер показал, что ниже 1.75 модель их теряет |
| `debug` | `false` | лог sherpa-onnx |

По движкам:

| `engine` | Обязательные ключи |
|---|---|
| `transducer` | `encoder`, `decoder`, `joiner`, `tokens` |
| `nemo-ctc` | `model`, `tokens` |
| `whisper` | `encoder`, `decoder`, `tokens`, необязательно `language` |

Дополнительно для BPE-моделей (zipformer-ru), чтобы подсказки можно было писать
обычными словами:

| Ключ | Значение |
|---|---|
| `bpe_vocab` | путь к словарю ssentencepiece (`tools/gen_bpe_vocab.py`) |
| `modeling_unit` | `bpe`; подставляется автоматически, если задан `bpe_vocab` |

Профиль не пройдет проверку, если хотя бы один обязательный файл отсутствует:
`AsrProfile::isValid()` возвращает подробную ошибку, она уходит в
`errorOccurred` и в лог — приложение не падает молча.

### Примеры профилей

```ini
[asr_zipformer-ru]
engine=transducer
encoder=sherpa-onnx-small-zipformer-ru-2024-09-18/encoder.int8.onnx
decoder=sherpa-onnx-small-zipformer-ru-2024-09-18/decoder.int8.onnx
joiner=sherpa-onnx-small-zipformer-ru-2024-09-18/joiner.int8.onnx
tokens=sherpa-onnx-small-zipformer-ru-2024-09-18/tokens.txt
bpe_vocab=sherpa-onnx-small-zipformer-ru-2024-09-18/bpe.vocab
modeling_unit=bpe
decoding_method=modified_beam_search
num_threads=2

[asr_gigaam-v3]
engine=transducer
encoder=sherpa-onnx-nemo-transducer-giga-am-v3-russian-2025-12-16/encoder.int8.onnx
decoder=sherpa-onnx-nemo-transducer-giga-am-v3-russian-2025-12-16/decoder.onnx
joiner=sherpa-onnx-nemo-transducer-giga-am-v3-russian-2025-12-16/joiner.onnx
tokens=sherpa-onnx-nemo-transducer-giga-am-v3-russian-2025-12-16/tokens.txt
decoding_method=greedy_search          ; GigaAM тяжёлый, луч тут дорогой
num_threads=2

[asr_whisper-base]
engine=whisper
encoder=sherpa-onnx-whisper-base/base-encoder.int8.onnx
decoder=sherpa-onnx-whisper-base/base-decoder.int8.onnx
tokens=sherpa-onnx-whisper-base/base-tokens.txt
language=ru
```

## `[vad]`

| Ключ | По умолчанию | Комментарий |
|---|---|---|
| `model` | `silero_vad.onnx` | путь (правила те же) |
| `threshold` | `0.5` | порог «речь / не речь» |
| `min_silence_duration` | `0.5` | секунды тишины, закрывающие сегмент. Больше — фразы длиннее и реже режутся |
| `min_speech_duration` | `0.25` | короче — не речь |
| `window_size` | `512` | сэмплов на окно (32 мс @ 16 кГц), не менять без нужды |
| `num_threads` | `1` | VAD лёгкий, одного потока хватает |
| `buffer_seconds` | `60` | размер кольцевого буфера детектора |

VAD в sherpa-onnx **не ресемплит**: `SileroVad` принимает только 16 кГц моно
int16 и сообщает об ошибке иначе. `QtAudioCapture` запрашивает ровно этот формат.

## `[text]`

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `auto_punctuate` | `true` | общий выключатель: заглавная в начале предложения и точка в конце |
| `capitalize` | `true` | заглавная в начале предложения (работает только при `auto_punctuate=true`) |
| `add_final_dot` | `true` | точка в конце сегмента (работает только при `auto_punctuate=true`) |
| `voice_punctuation` | `true` | «точка» → `.`, «запятая» → `,` и т. д. |

`capitalize` и `add_final_dot` выделены из `auto_punctuate`, потому что точка
в конце нужна не всегда: диктовка отдельных слов, поисковых запросов, паролей.

Подробности и таблица слов — в
[hotwords-and-punctuation.md](hotwords-and-punctuation.md).

## `[output]`

| Ключ | По умолчанию | Комментарий |
|---|---|---|
| `method` | `auto` | `auto` — буфер обмена, если есть `xclip`/`xsel`/`wl-copy`, иначе `xdotool type`; `clipboard` — только буфер; `xdotool` — только посимвольный ввод |
| `typing_delay_ms` | `12` | задержка между символами в режиме `xdotool type` |
| `space_between_segments` | `true` | добавлять пробел между фразами: VAD отдаёт речь кусками, каждый вставляется отдельным вызовом |
| `preserve_clipboard` | `true` | запомнить прежний текст буфера и вернуть его после вставки |
| `clipboard_restore_ms` | `1000` | через сколько миллисекунд возвращать буфер |
| `pin_window` | `false` | вставлять в окно, активное в **начале записи**, а не в то, что в фокусе сейчас |

Вставка через буфер затирает его содержимое — это неизбежная плата за независимость
от раскладки. При `preserve_clipboard=true` прежний **текст** возвращается обратно
через `clipboard_restore_ms`. Картинки и прочие mime-типы не сохраняются.
Задержку стоит увеличить, если целевое приложение медленное и иногда вставляет
уже восстановленное содержимое.

Буфер обмена предпочтительнее: `xdotool type` для кириллицы требует русской
раскладки в момент ввода (иначе вместо «привет» уедет «ghbdtn») и медленнее.
Обратная сторона — затирается содержимое буфера обмена.

### `pin_window` — вставка в окно, а не в фокус

Результат приходит через 0.5–2 с после произнесённой фразы и по умолчанию уходит
в то окно, которое в фокусе **в этот момент**. Стоит переключиться, чтобы сделать
пометку в другом файле, — и продиктованное прилетит туда.

`pin_window=true` запоминает `xdotool getactivewindow` в начале записи и вставляет
в него (`xdotool type --window WID` / `key --window WID ctrl+v`): можно
переключиться и печатать руками, пока диктовка продолжается.

⚠️ **Проверьте на своём редакторе.** `xdotool --window` доставляет события через
`XSendEvent`, и часть приложений такие события игнорирует (чаще всего это
заметно на способе `clipboard`, потому что там отправляется `Ctrl+V`). Если ввод
не проходит — выключите `pin_window` и используйте заметки в файл (см. `[notes]`):
они от фокуса не зависят вообще.

## `[commands]`

| Ключ | По умолчанию | Комментарий |
|---|---|---|
| `editing_in_dictation` | `false` | выполнять ли команды правки в режиме диктовки |
| `file` | `~/.config/voice-assistant/commands.txt` | свой файл команд |

Формат своего файла — `фраза = тип[:аргумент]`, по одной команде в строке,
`#` — комментарий:

```
# фраза            = тип[:аргумент]
открой консоль     = new-line
шумный режим       = set-mode:edit
кавычка            = punctuation:"
```

Типы: `set-mode:{dictation|edit|spellcheck|off}`, `delete-word`, `delete-line`,
`new-line`, `space`, `punctuation:<символ>`. Битые строки пропускаются с
предупреждением в лог, а не роняют загрузку.

## `[notes]` — заметки в файл

Вторая цель вывода. Распознанный текст дописывается в файл вместо активного
окна. Ни фокус, ни клавиатура, ни буфер обмена не участвуют, поэтому пометки
к файлу, с которым работаешь, можно диктовать, продолжая печатать руками.

| Ключ | По умолчанию | Комментарий |
|---|---|---|
| `enabled` | `true` | создавать ли файл заметок при старте |
| `dir` | `~/.local/share/voice-assistant/notes` | каталог ежедневных файлов; `~` раскрывается, относительный путь считается от домашнего каталога |
| `file` | *(пусто)* | явный файл **вместо** ежедневного, например `~/work/notes.md` |
| `timestamp` | `HH:mm:ss` | метка времени в начале строки; пусто = писать текст как есть |
| `markdown` | `true` | `true` — файл `.md` и строки вида `- 14:03:22 — текст`; `false` — `.txt` без маркеров |
| `day_header` | `true` | заголовок `# Заметки YYYY-MM-DD` при создании файла дня |
| `voice_commands` | `true` | голосовые фразы переключения цели (см. ниже) |
| `start_target` | `focus` | с какой целью запускаться: `focus` или `notes` |

Результат — один файл на день:

```markdown
# Заметки 2026-10-03

- 14:03:22 — Проверить, как ведёт себя AGC на тихом микрофоне
- 14:07:51 — В gazeta.ru сегменты режутся на «Профессиональный боксёр»
```

**Как переключать цель вывода**

| Способ | Действие |
|---|---|
| голосом | «заметка», «в заметки», «пиши в заметки» → файл; «в редактор», «в окно» → окно |
| из трея | пункт «Писать в файл заметок» (галочка), «Открыть заметки» |
| по D-Bus | `setOutputTarget "notes"`, `toggleOutputTarget`, `getOutputTarget`, `notesFile` |
| из консоли | `./src/voice-assistant --note "текст"` — дописать и выйти |
| в конфиге | `start_target=notes` — запускаться сразу в заметки |

Голосовые команды переключения цели работают **и в режиме диктовки**, даже при
`[commands] editing_in_dictation=false`: это маршрутизация, а не правка текста.
Командой считается только фраза, совпавшая целиком, поэтому «сделать заметку
на полях» остаётся обычным текстом. Если слово «заметка» всё равно мешает —
`voice_commands=false`, и цель переключается только из трея и по D-Bus.

Команды правки в этой цели применяются к последней строке файла: «удали слово»
стирает последнее слово последней заметки, «новая строка» добавляет пустую
строку. Остальные (`shift+Home` и т. п.) к файлу неприменимы и просто
пропускаются — это не ошибка.

**Проверить без микрофона**

```bash
./src/voice-assistant --note "проверка"          # дописать строку в файл дня
./tools/vad-asr-test запись.wav --config ~/.config/voice-assistant/settings.ini --notes
```

Вторая команда прогоняет WAV боевым путём (VAD → ASR → пунктуация) и складывает
сегменты в тот же файл заметок: так проверяется вся цепочка вывода без X-сервера.

## `[spellcheck]`

| Ключ | По умолчанию | Комментарий |
|---|---|---|
| `enabled` | `true` | включать ли проверку правописания вообще |
| `lang` | `ru_RU` | имя словаря: ищутся `<lang>.aff` и `<lang>.dic` |
| `dictionary_dir` | пусто | каталог словаря; пусто = стандартные пути |
| `max_suggestions` | `5` | сколько вариантов исправления предлагать |

Стандартные пути поиска: `/usr/share/hunspell`, `/usr/share/myspell`,
`/usr/local/share/hunspell`, `~/.hunspell`, `~/.local/share/hunspell`.

Словарь обязан быть в **UTF-8** — `HunspellChecker` проверяет кодировку через
`Hunspell_get_dic_encoding()` и отказывается работать с KOI8-R/ISO8859-5,
поскольку текст из ASR приходит в UTF-8 и сравнивается побайтово.

Отсутствие hunspell не ломает сборку: зависимость детектируется pkg-config,
без неё `initialize()` возвращает false с внятным сообщением.

## `[hotkey]`

| Ключ | По умолчанию | Комментарий |
|---|---|---|
| `backend` | `evdev` | `evdev` или `off` |
| `key` | `KEY_F8` | `F8`, `KEY_F13`, `ctrl+space`, `Ctrl+Alt+Shift+F13` или числовой код (`66` = `KEY_F8`) |
| `mode` | `push_to_talk` | `push_to_talk` (держим клавишу) или `toggle` (нажал/отжал) |
| `grab` | `false` | `true` = `EVIOCGRAB`, эксклюзивный перехват устройства |
| `grab_devices` | *(пусто)* | какие устройства разрешено перехватывать: подстрока имени или путь, через запятую |

evdev читает `/dev/input/event*` напрямую, поэтому хоткей работает в X11,
Wayland и голой TTY — системе эта клавиша не нужна. Требуется доступ:

```bash
sudo usermod -aG input $USER     # затем перелогин
```

### Клавиатура не блокируется

По умолчанию `grab=false`: evdev **только слушает** `/dev/input/event*`, ничего
не перехватывая. Печатать во время диктовки можно всегда — это требование,
а не режим: диктовка не должна превращаться в работу, при которой нельзя
сделать пометку руками.

Единственный побочный эффект режима наблюдения — клавиша хоткея доходит и до
активного приложения. Лечится это **выбором клавиши**, а не перехватом:
`F13`–`F24`, `Scroll Lock`, `Pause`, `Mic Mute`, правый `Ctrl` или комбинация
(`ctrl+alt+f8`). `--check` печатает этот совет, если клавиша выглядит занятой.

⚠️ **`grab=true` отдаёт устройство эксклюзивно**: X-сервер перестаёт получать
с него **все** клавиши, а не только наш хоткей. Смысл имеет лишь для выделенной
педали или второй клавиатуры, и даже тогда устройство лучше назвать явно:

```ini
[hotkey]
grab=true
grab_devices=/dev/input/event9, Foot Switch
```

Предохранитель: при `grab=true` и пустом `grab_devices` устройство, похожее на
полноценную клавиатуру (в маске `EVIOCGBIT(EV_KEY)` есть буквы **и** цифры),
**не перехватывается** — в лог пишется, почему. То есть основная клавиатура
не уйдёт из-под X, даже если `grab=true` включить по ошибке; для явного
перехвата её нужно назвать в `grab_devices` целиком (путём).

Если клавиша всё-таки мешает приложению, а грабить устройство не хочется —
есть третий путь: `[hotkey] backend=off` и назначение клавиши средствами WM/DE
на D-Bus-вызов (см. ниже). Тогда события читает система, а не мы.

Без прав на `/dev/input` хоткей не запускается, но приложение работает:
режимы переключаются из трея и по D-Bus. Альтернатива без кода и без прав —
повесить клавишу в настройках WM на D-Bus-вызов:

```bash
dbus-send --session --type=method_call --dest=org.voiceassistant.App \
  /org/voiceassistant/App org.voiceassistant.App.startRecording
```

### `typing_guard_ms` — стук клавиш вместо слов

Если диктовать и одновременно печатать, микрофон ловит стук клавиш, VAD делает
из него сегмент, и в текст вставляется мусор; кроме того, продиктованное
вклинивается в напечатанное с опозданием на 0.5–2 с.

evdev читается и так (глобальный хоткей), поэтому момент нажатия любой клавиши
известен. Пока с последнего нажатия прошло меньше `typing_guard_ms`, кусок аудио
не уходит в VAD/ASR. Клавиша самого хоткея и модификаторы из его комбинации
печатью не считаются — иначе `ctrl+space` глушил бы сам себя.

* Работает только при `[hotkey] backend=evdev`: события клавиш берутся оттуда.
* По умолчанию выключено: если говорить и печать **одновременно**, речь режется.
* Запись в WAV (проверка микрофона) не прерывается — снимок тракта обязан
  показывать всё, иначе его нельзя сравнивать с тем, что слышит ASR.
* По окончании записи в лог пишется, сколько аудио выброшено:
  `Глушитель печати: выброшено 12 кусков аудио (0.60 с)`. Если секунд много —
  значение стоит уменьшить. Разумная отправная точка — `150`–`250` мс.

|---|---|
| `--record <сек> [файл.wav]` | записать с микрофона в WAV и выйти; сырой тракт, **без AGC** и без GUI |
| `--note <текст>` | дописать строку в файл заметок и выйти; без микрофона, GUI и X-сервера |
| `--check` | диагностика конфигурации и моделей, без GUI и микрофона; код возврата 0 — всё на месте, 1 — есть проблемы |
| `--config <путь>` | использовать указанный `settings.ini` вместо `~/.config/voice-assistant/settings.ini` (работает и с `--check`, и с `tools/vad-asr-test`) |

## Смена профиля в рантайме

```cpp
controller.switchAsrProfile(QStringLiteral("gigaam-v3"));
```

Старая модель выгружается (`unique_ptr` сбрасывается до создания новой), ОЗУ
освобождается. Переинициализация стоит 1.2–5.1 с, поэтому делать её стоит
по явному действию пользователя, а не автоматически.
